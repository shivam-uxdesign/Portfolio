Rupyy Design Kit · Overview
01The tension

Four places, four versions of the truth.

Our PMs already prototyped in Claude Design. It's fast for a single screen, but every prototype carried its own copy of our design system. Journey Studio and Illustration Studio, which I built with Claude, carried theirs, and Figma held the library. When Claude needed a value it didn't have, it picked a close one, so the first question in every review was which green was the right one.

  • Copies driftFive studio exports held 43 tokens that disagreed with the Figma library.
  • AI fills gapsAsked for a part it didn't have, Claude invented one that was nearly right.
  • Changes stop shortA Figma update reached Figma. Screens and graphics kept the old value.
  • No one to askPMs couldn't tell which version was right, so every review started there.
02The insight

AI-built tools need a contract, not a library.

A library is something people browse. Claude doesn't browse; it reads what it's given and builds. So the kit is written like an API: a versioned catalogue Claude reads before it builds any screen part, and a rule that nothing reaches a tool except through a release.

01One core, thin layers

Tokens and parts live once. Each product adds only what truly differs: its density and its own parts.

02Released, not synced

Studios change only when a release is applied, so a half-made change never breaks a review.

03Read before you build

Every studio's Claude reads the catalogue first and uses kit classes exactly. No hex, no new class.

04Figma stays the master

Designers design in Figma; everyone else builds from the kit. A parity check keeps them equal.

03The build

A core, a layer per product, and a release.

The Figma layer

Where the system is designed

Everything in the kit starts in our Figma library. A year ago that library was 15 colour swatches and three button styles. I rebuilt it as 1,637 variables in three tiers and wired the components to them, so the kit has something exact to match.

2025 · Library v1

  • 282icon variants for 60 icons, one copy per size

Bound variables

Change a property and the button and its variables update. The panel is rebuilt from the button's real properties and bindings in our library: 5 sizes × 4 variants × 4 types × 4 states × 2 radii, on 198 button variables.

These variable names are what the parity check compares with the kit.

Core plus thin product layers

Only density changes

Every product is the core plus a thin layer. The layer changes density, the padding and spacing that suit how that team works, and nothing that carries the brand or meaning: colour, type, radius, status colours and button sizes stay in the core. Publishing rebuilds each product's theme, so studios still get one complete theme.

      Looking back
  
      
    
      What I learned
      
        
        
      1. Write the system for its reader.Claude reads the kit, so I wrote it like an API: a do, a don't and exact markup. That did more for consistency than any style guide.
        2. 
        
      2. Truth depends on who's asking.Designers need Figma; PMs and tools need a release. Naming both ended the "which one is right" debate.
        3. 
        
      3. Strict rules keep layers thin.Once a product could only change spacing, products stopped drifting apart.
        4. 
      
      
    
      What I'd do differently
      
        
        
      1. Build the checks before the parts.The review checks stopped more drift than the first three releases did. I'd start with them.
        2. 
        
      2. Put PMs in the loop from day one.The PM approval step came late. It belongs in the very first release.
        3. 
        
      3. Bring a developer in early.So tokens reach production code from the start, not only prototypes.
        4. 
      
      
    
      What's next
      
        
        
      1. Tokens in production.The same releases feed the live app, with 0 raw values in shipped screens as the bar.
        2. 
        
      2. Fix our own contrast.White on the brand green is 2.3:1. Agree a darker button green with brand.
        3. 
        
      3. Usage before change.Live where-used from every studio, so each part shows what it touches before it changes.
